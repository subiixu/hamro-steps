## What the user asked
Four small follow-ups from the merged Convex activity and push work (T-7, T-9): hide the debug sample-account button on live launches, decode a missing/null feed actor name in the model, scroll to and highlight the event a tapped notification is about, and stop the device-call cancellation tests from hanging if cancellation regresses.

## What changed
1. **Debug button:** Welcome's "Use the sample account (debug)" now shows only when `AppLaunch.isMockLaunch` (still inside `#if DEBUG`), since the real `/auth/apple` rejects the sample token.
2. **FeedActor.name:** `FeedActor` decodes `name` with `decodeIfPresent(...) ?? ""` (explicit memberwise init kept). `ConvexActivityService.feed` now decodes `[FeedEvent]` directly; the private `WireFeedEvent` is gone. `feedDecodes` still checks the `name: null` → `""` row, now through the model.
3. **Push tap focus:** `HomeModel` has `focusEventId`, `focus(eventId:)` and `takeFocus()` (handed out once). `PushInbox.open` sets it after selecting the family when the route carries an `eventId`. HomeView wraps its ScrollView in a `ScrollViewReader`; once the selected family's feed is no longer loading it takes the focus, reloads the feed if the event isn't in it yet (a push for the family already on screen), then scrolls the row to the centre and gives it a soft accent background (`.accent.opacity(0.12)`, rounded) for 2.5 s, fading out. If the event still isn't there (or the feed failed), the focus is just dropped and the family shows as before. `FeedList`/`FeedCard` take an optional `highlightedEventId`; rows carry `.id(event.id)`.
4. **Test watchdogs:** `waitUntilHanging` is bounded (2 s, returns Bool, `#expect`ed). The two cancellation tests and the already-cancelled test start `releaseAfterDeadline()` (opens the gate after 1 s unless cancelled), so a regression fails the CancellationError / <100 ms checks instead of hanging. `HangingTransport` records hanging calls in `hangingCalls`; the already-cancelled test asserts it's empty.

**Second-review fixes (18:1x):**
- `HomeView.showFocusedEvent` keeps its work in `@State focusTask`; a new tap cancels the previous one. The feed reload runs in its own unstructured task (so cancelling a focus never marks the feed failed), and after every await it checks the task isn't cancelled, `self.feed === feed` and `home.selectedFamilyId == feed.familyId` before scrolling or highlighting, so a slow reload for an older tap can't override a newer one.
- `alreadyCancelledDeviceCallSendsNothing`: after the call returns, it waits up to 300 ms for a delayed send to reach the hanging transport (`#expect(await h.waitUntilHanging(deadline: .milliseconds(300)) == false)`) before asserting `hangingCalls` is empty.

Tests added: `HomeModelTests.focusEventIsHandedOutOnce`, `PushTapTests.tapWithoutAnEventShowsTheFamilyWithNoFocus`; `tapDuringOnboardingOpensItsFamilyOnceHomeShows` now checks the focus is `e_1`, and the not-in-family test checks no focus is set.

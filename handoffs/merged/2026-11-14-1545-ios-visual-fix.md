## What changed
1. **Settings, invite card seam:** the code card now sits inside the list row (new `embedded` option on `InviteCodeCard`), so the code, Share invite and Get a new code read as one rounded group with full-width dividers.
2. **Join, Paste button:** tinted with the new AA accent. It was pale in the old shot because the clipboard was empty and the system dims `PasteButton` then. With a code on the clipboard it's dark orange with white text (checked).
3. **Home at accessibility sizes:** header is top-aligned. The chevron sits on the title's first line (scaled offset) and the settings button stays at the top. Ring capped at 240pt (was 300).
4. **Settings, remove member:** now a visible "Remove" label plus icon in the AA accent. VoiceOver label is still "Remove <name>".
5. **Me:** "Delete account" uses system red (the brief allows it). Sign out and other list tints use the AA accent.
6. **Tab bar:** Home gets a 72pt bottom content margin, so the last card clears the floating tab bar at the end of the list.
7. **Welcome:** feature lines now take the full width (no early wrapping).
8. **Me top spacing:** the navigation bar is hidden and "Me" is a custom large title, like Home's header. The two titles now start at the same height.
9. **Grey text contrast:** two new colour assets with dark variants, exposed in `Palette.swift`:
   - `SecondaryText` (#6B625B light / #B5ABA2 dark, about 5.7:1 on canvas). Every `.foregroundStyle(.secondary)` in Features and Components uses it, as do the Settings and Me list headers and footers.
   - `AccentText` (#B5481B light / #F28A52 dark, about 5.2:1 on canvas). Use it for accent text and links.
   - The selected goal preset is now canvas-on-AccentText, which passes AA in both modes. Before, it was white on accent: 3.3:1.
- **Review 2:** at accessibility sizes, `GoalPicker` shows the number full width with − / + underneath. The number uses lineLimit 1 and shrinks to at least 0.5 scale; `fixedSize` is gone. Verified at 50,000 and 1,000,000. For screenshots, a DEBUG-only `-goal <n>` launch argument sets `CreateGoalView`'s starting goal.
- **Review 3:** the Health row says **"Permission asked"** in neutral colours, plus "No steps read yet…", until `stepSync.lastSyncedAt` exists. `StepSync.sync()` only sets that after reading non-zero steps. Only then does it say **"Reading steps"** with a green icon and "Steps last sent …". The recovery footer stays visible whenever permission has been asked. I didn't touch the model.

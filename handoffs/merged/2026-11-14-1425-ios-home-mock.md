## What the user asked
Build the iPhone app's v1 flows (PRD F1–F8): Sign in with Apple, the Health permission screen, creating or joining a family, Home (progress ring, contributions, last synced, this week), family settings, Me with account deletion, and Nepal-day step sync with HealthKit background delivery. All of it runs against a `FamilyService`/`AuthService` protocol pair with in-memory mocks, so the Convex phase only swaps the implementation. (T-4, T-5, T-6)

## What changed
**Done: everything in the brief except the screenshots.** The app builds with no warnings, and all checks pass.

- **Navigation:** two tabs, **Home** and **Me**. A first launch goes Welcome → first name (only when Apple sends none) → Health → create or join → Home. The old Today tab, the Family placeholder, the streak card, the fire and cheer icons and colours, and the "Family goal" placeholder are all gone. Nothing anywhere is red or ranked.
- **Services** (`ios/HamroSteps/Services/`):
  - `FamilyService` mirrors the Convex API reference in `handoffs/2026-11-14-1403-convex-core.md`: `createFamily`, `previewInvite`, `joinFamily`, `regenerateInviteCode`, `removeMember`, `updateFamily`, `leaveFamily`, `myFamilies`, `syncSteps` (returns `{lastSyncedAt, today}`), `deleteMyAccount`, `familyToday`, `familyWeek` (the `{today, weekStart, startsAt, days}` envelope), and `familyTodayUpdates -> AsyncStream`.
  - `AuthService` has `signInWithApple(identityToken:authorizationCode:fullName:timeZone:)` (Jarvis's addition, plus the timezone from `/auth/apple`), `updateName` (maps to `updateProfile({name})` then `me()`), `signOut`, `deleteAccount`, and `currentUser`.
  - Both services are injected through `EnvironmentValues` (`\.familyService`, `\.authService`). The concrete ones are built in one place, `AppLaunch.services()` in `HamroStepsApp.swift`.
  - `FamilyServiceError` covers all 11 backend codes, including `cannot_remove_self` and `invalid_token`, with friendly, non-blaming messages.
- **Models** (`ios/Shared/Models/Family.swift`) match the backend JSON:
  - `FamilySummary` has `FamilyView`'s fields `{familyId, name, dailyGoal, inviteCode, organiserId, memberCount, isFull}`, plus the optional `isOrganiser` and `position` that `myFamilies` adds. I kept the Swift name `FamilySummary` so it isn't mistaken for a SwiftUI view.
  - `AppUser` matches `me()`, with `needsName`.
  - The rest: `InvitePreview`, `FamilyMember` (a `null` name decodes to empty), `FamilyToday`, `FamilyWeek`, `FamilyWeekDay` (with `isBeforeFamily`), `StepDay`, `SyncStepsResult`.
- **Mocks:** `MockFamilyService` is an actor that follows the backend rules: fixed order, the organiser role passing on, an empty family being deleted, 8-member cap, Nepal-day validation, and live updates after every change.
  - Sample data: "Thapa Family" has 5 people in fixed order; Bikash has `steps: nil`. "Sydney Cousins" gives the switcher a second family. A full family uses code `WXYZ22`.
  - `MockAuthService` remembers "signed in" across launches. Welcome has a debug-only "Use the sample account" button, because the real Apple sheet needs a signing team.
- **Screens:**
  - **Welcome:** a real `SignInWithAppleButton` asking only for the full name.
  - **Name:** asked only when `needsName`.
  - **Health:** plain-words reasons, then the system permission sheet.
  - **Create:** family name → goal (50,000 suggested; presets 30k/50k/75k/100k; ±5,000; range 1,000–1,000,000) → invite code in big type with Copy and Share. The share message is WhatsApp-friendly; the TestFlight placeholder lives in one constant, `InviteMessage.installURL`.
  - **Join:** the code field ignores case, spaces and dashes. `PasteButton` pulls the code out of a whole pasted invite message. Once the code is complete, `previewInvite` shows the family's name and member count before joining. "Code not found", "family is full" and "already a member" each get friendly copy.
  - **Home:**
    - Header: family name, a switcher menu (including "Add another family"), and a settings button.
    - Progress ring: past 100% it turns the goal green, draws a second lap and shows a celebrate icon; the percentage isn't capped.
    - "Your steps synced 5 minutes ago".
    - Contributions in `position` order, "not synced yet" for `nil`, and a small crown with "Organiser" for the organiser.
    - The week: hit / not hit (neutral grey) / future (dashed) / before the family existed (faded).
    - Pull to refresh syncs and reloads. Accessibility sizes switch rows to a stacked layout so numbers never truncate.
  - **Family settings:**
    - The organiser can edit the name and goal, share the code, get a new code (with confirmation) and remove a member (with confirmation).
    - Everyone can leave. If the organiser leaves, the dialog names who takes over.
  - **Me:** name, Apple Health status (connected / not connected / unavailable, with last sent), Sign out (with confirmation), and **Delete account** in two steps: an explanation page, then a final "Delete permanently" dialog. The backend `deleteMyAccount` runs first; if it fails, the person stays signed in and sees a message.
- **Step sync (`HamroSteps/Sync/StepSync.swift`):**
  - HealthKit is bucketed by Nepal days (`NepalDay.calendar`, Asia/Kathmandu, weeks start Monday). It sends 7 days, oldest first, today last, with steps clamped to 0–200,000.
  - It runs on foreground, on pull-to-refresh, after sign-in and from background delivery. `HKObserverQuery` plus `enableBackgroundDelivery(.hourly)` are registered in the app delegate at launch, and the completion handler is always called exactly once.
  - `lastSyncedAt` is kept in UserDefaults.
  - A week with no steps at all isn't sent, so a person who switched Health off stays "not synced yet" instead of showing 0.
- **Entitlements bug fixed:** the scaffold's `.entitlements` file was empty. XcodeGen rewrites that file from `project.yml` on every generate, so the HealthKit entitlement never actually applied. The entitlements now live in `project.yml` under `entitlements.properties`: HealthKit, HealthKit background delivery and Sign in with Apple.
- **Debug launch arguments**, for screenshots: `-screen welcome|name|health|setup|create-name|create-goal|invite|join|home|settings|me`, `-signedOut`, `-newUser`, `-mockSteps`, `-mockStepsLoading`.

## What the user asked
Phase 1 of the iPhone app: a buildable, tested SwiftUI app in `ios/`, generated by XcodeGen. It needed the Today / Family / Me tab shell, a HealthKit step reader behind a `StepSource` protocol, Hugeicons as template vector assets, and ThinkingOrbsKit as the only loading indicator.

## What changed
- **Project:** `ios/project.yml` is the source of truth. App `HamroSteps` (`com.bixustudio.hamrosteps`, iOS 26.0, iPhone only, portrait, Swift 6 with strict concurrency set to complete), hosted unit tests `HamroStepsTests`, and a shared `HamroSteps` scheme that runs them. The Info.plist is generated from build settings, including `NSHealthShareUsageDescription` with the exact wording from the brief. The HealthKit entitlement is in `HamroSteps/Resources/HamroSteps.entitlements`. The generated `.xcodeproj`, `DerivedData/`, `xcuserdata/` and `build/` are listed in `ios/.gitignore`.
- **Folder layout, ready for a widget:**
  - `ios/Shared/` holds the models (`DailySteps`, `StepSummary`), the `StepSource` protocol, `StepHistory` (fills a 7-day window, missing days count as zero), `MockStepSource`, `StepFormatter`, `Icon` and `Palette`. It also has `SharedAssets.xcassets` with the icons and colours. Nothing in it imports HealthKit or ThinkingOrbsKit, so a WidgetKit target can add `- path: Shared` to its sources later without moving anything.
  - `ios/HamroSteps/` holds app-only code: `HealthKitStepSource`, `StepStore`, `OrbLoader` and the screens.
- **HealthKit:** `HealthKitStepSource` only reads `stepCount`. It runs one `HKStatisticsCollectionQuery` (cumulative sum, 1-day buckets anchored at local midnight in the given calendar). The HealthKit errors for no data, permission not yet asked, and permission denied all come back as empty data, not an error.
- **Permission flow:** the first launch shows "Connect Apple Health" (with a "Not now" option). After that the user always lands on the tabs. HealthKit doesn't tell apps when reading was denied, so a week of all zeros shows a hint on Today ("Seeing zeros? Open the Health app → Sharing › Apps › Hamro Steps…") instead of an error. If Health isn't available on the device, a message says so. If a read fails, the user gets a "Try again" button, and any numbers already loaded stay on screen. Steps refresh on pull-to-refresh and whenever the app comes back to the foreground.
- **Today tab:** large rounded number for today's steps (`.monospacedDigit()`, numeric transition), the week total, a 7-day bar chart with today highlighted, and placeholder cards for the family goal and streak. **Family** and **Me** are placeholder screens (create/invite buttons are disabled and marked "Coming soon"; settings rows have no actions yet).
- **Icons:** 10 icons from the Hugeicons free set (`@hugeicons/core-free-icons` 4.4.0, MIT), all stroke-rounded at a 1.5 stroke. Each is an SVG imageset with Preserve Vector Data and template rendering: home → footprints, family → user-group, profile → user, settings → settings-01, plus → add-01, chevronRight → arrow-right-01, fire, cheer → clapping-01, goal → target-02, share → share-08. In code, `Icon.home` is a view (24pt; `.size(_:)` changes it) and `Icon.home.image` gives a bare `Image` for tab items. There are no SF Symbols or emoji.
- **Colours:** named colours in the asset catalog, each with a dark variant: `AccentColor` (warm orange), `Canvas`, `Surface`, `SurfaceMuted`, `Streak`, `Cheer`, `Goal`. Views use `.canvas`, `.accent` and so on, or system semantic styles like `.primary`. There are no colour literals in views.
- **Loading:** `OrbLoader` wraps `ThinkingOrb` (`.working` while counting steps, `.connecting` while asking Health for permission; 64pt, plus a 20pt compact version). `ProgressView` isn't used anywhere.
- **Debug-only launch arguments** for the simulator and screenshots: `-mockSteps` (sample week, skips the first-launch screen), `-mockStepsLoading` (never finishes loading), `-showOnboarding`.

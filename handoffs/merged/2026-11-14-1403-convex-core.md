## What changed
A complete Convex backend in `backend/`, using strict TypeScript and 48 convex-test/vitest tests. Nothing is deployed to the cloud. Codegen came from an anonymous local deployment, and `convex/_generated/` is included.

- **Sign-in (F1).** The iOS app posts Apple's identity token. The server checks it against Apple's keys, finds or creates the user, and returns our own 1-hour access JWT and a 90-day refresh token. Refresh tokens rotate on every use. Reusing an old one signs that device's session out. Convex reads our JWT through `auth.config.ts`, so `ctx.auth.getUserIdentity().subject` is the `users` id.
- **Account deletion (F1).** It revokes the Apple sign-in first, then removes the user, their memberships, their steps in every family's closed days, steps, sessions and tokens. Organiser goes to the earliest-joined remaining member, and a family left empty is deleted with its history. With no Apple env vars set, the revoke is skipped with a log line. If Apple can't be reached or refuses, or the Apple env is missing while a token is stored, the account is still deleted (deletion never depends on Apple). In the same transaction the Apple token goes into `appleRevocations`, retried after 1 min, 10 min, 1 h, 6 h, then daily, forever. The row is deleted only when Apple confirms the revoke. An hourly cron (minute 30) reschedules any row more than 15 min past its `nextAttemptAt`, so a lost scheduled run can't strand it. Each run carries its attempt number, so a doubled run can't fork the retry chain.
- **Leaving and removal (F2, F3).** The member's steps come out of that family's closed days: each day's total and hit are recomputed against its frozen goal, so a day can flip back from hit. Other families they're still in keep counting them.
- **Families (F2, F3).** Create, preview an invite, join, update, regenerate the code, remove a member and leave. Codes are 6 characters, and joining ignores case, spaces and dashes. Joining twice is harmless, and a 9th member gets `family_full`. Order is fixed by `position` (join order, organiser first), never by steps.
- **Steps (F4, F5).** `syncSteps` takes today plus up to the previous 6 Nepal days and replaces each stored value. When a value changes for a day that has already closed, the user's contribution to every family that counted them at that close is updated and the snapshot total and hit recomputed.
- **Home (F6–F8).** `familyToday` returns members in fixed order. A member who hasn't synced today has `steps: null`, never 0. `familyWeek` covers Monday to Sunday of the Nepal week, using frozen-goal snapshots for closed days and live totals for today.
- **Midnight cron.** It runs daily at 18:15 UTC and snapshots each family's total, goal and hit into `familyDays`, plus one `dayContributions` row per member at the close (0 for anyone unsynced). A snapshot's total is always the sum of its contributions. Running it twice does no harm. A second daily cron purges expired refresh tokens.

## API reference (for the iOS app and phase 2)
Errors are `ConvexError({ code })`, with these codes: `not_authenticated`, `invalid_code`, `family_full`, `not_member`, `not_organiser`, `invalid_goal`, `invalid_name`, `invalid_steps`, `invalid_day`, `cannot_remove_self`, `invalid_token`. The last two are new. A family id that doesn't exist also returns `not_member`.

**HTTP (JSON).** Errors are `{code}` with 400 `invalid_request`, 401 `invalid_token`, or 503 `apple_unavailable`.
- `POST /auth/apple` takes `{identityToken, authorizationCode?, fullName?: string | {givenName?, familyName?}, timezone?}` and returns `{accessToken, accessTokenExpiresAt, refreshToken, refreshTokenExpiresAt, userId, isNewUser, name: string|null, needsName}`.
- `POST /auth/refresh` takes `{refreshToken}` and returns `{accessToken, accessTokenExpiresAt, refreshToken, refreshTokenExpiresAt, userId}`. The old refresh token is dead after this call.
- `POST /auth/logout` takes `{refreshToken}` and returns 204.
- `GET /.well-known/jwks.json` serves our public key.

Time fields are epoch milliseconds. Access JWT claims are iss = `CONVEX_SITE_URL`, aud = `hamro-steps`, sub = users id.

**users.ts**
- `me()` returns `{userId, name|null, needsName, avatarColor, timezone|null, lastSyncedAt|null}`.
- `updateProfile({name?, timezone?})` returns `null`. Names must be 1–40 characters after trimming.
- `deleteMyAccount()` is an action and returns `{appleRevoke: "revoked"|"skipped"|"queued"}`. `"skipped"` now only means no Apple token was stored. `"queued"` means the account is deleted and the Apple revoke will be retried until Apple confirms it, including when the Apple env is missing. The app can treat all three as success.

**families.ts.** `FamilyView` is `{familyId, name, dailyGoal, inviteCode, organiserId, memberCount, isFull}`.
- `createFamily({name, dailyGoal? = 50000})` returns `FamilyView`. The goal must be a whole number from 1,000 to 1,000,000.
- `previewInvite({code})` returns `{familyId, name, memberCount, isFull, alreadyMember}`. It's for the join screen.
- `joinFamily({code})` returns `FamilyView`.
- `myFamilies()` returns `[FamilyView & {isOrganiser, position}]`, in the order the user joined them.
- `updateFamily({familyId, name?, dailyGoal?})` returns `FamilyView`. Organiser only.
- `regenerateInviteCode({familyId})` returns `{inviteCode}`. Organiser only.
- `removeMember({familyId, userId})` returns `null`. Organiser only.
- `leaveFamily({familyId})` returns `null`.

**steps.ts**
- `syncSteps({days: [{day: "YYYY-MM-DD", steps}]})` returns `{lastSyncedAt, today}`. The whole batch is validated before anything is written.

**home.ts**
- `familyToday({familyId})` returns `{family: FamilyView, day, goal, total, percent, members: [{userId, name|null, avatarColor, position, isOrganiser, steps|null, lastSyncedAt|null, status: null}]}`. `percent` is a whole number and not capped at 100.
- `familyWeek({familyId})` returns `{today, weekStart, startsAt, days: [{day, total, goal, hit, isFuture, isBeforeFamily}]}`. `isBeforeFamily` is an addition: true for days before the family was created, so the app can grey them out.

**Internal functions:** `days.closeDay({day?})`, `sessions.signInWithApple`, `sessions.rotateRefreshToken`, `sessions.revokeSession`, `sessions.purgeExpired`, `users.appleTokenFor`, `users.deleteAccountData({userId, revokedAppleToken?})` → `{queued}`, `users.retryAppleRevoke({id, attempt})` (scheduled), `users.pendingRevocation({id, attempt})`, `users.recordRevokeAttempt({id, attempt, revoked})`, and `users.recoverAppleRevocations()` → `{rescheduled}` (hourly cron).

**Schema (`convex/schema.ts`):**
- `users`: appleSub, name?, avatarColor, timezone?, lastSyncedAt?, createdAt. Index `by_appleSub`.
- `appleTokens`: userId, refreshToken. Index `by_user`.
- `appleRevocations`: refreshToken, attempts, nextAttemptAt, createdAt. Index `by_nextAttemptAt`. Not linked to a user. Holds tokens not yet confirmed revoked at deletion, until Apple confirms.
- `sessions`: userId, revokedAt?. Index `by_user`.
- `refreshTokens`: sessionId, userId, tokenHash (SHA-256), expiresAt, usedAt?. Indexes by_hash, by_session, by_user, by_expiresAt.
- `families`: name, dailyGoal, inviteCode, organiserId, nextPosition, createdAt. Index by_inviteCode.
- `memberships`: familyId, userId, position, joinedAt. Indexes by_family_position, by_family_user, by_user.
- `dailySteps`: userId, day, steps, updatedAt. Index by_user_day.
- `familyDays`: familyId, day, goal, total, hit, closedAt. Index by_family_day.
- `dayContributions`: familyId, day, userId, steps. Indexes by_family_day, by_user_day, by_user_family. Written at the close; `lib/totals.ts` `recomputeSnapshot` sums them into `familyDays.total`.

**Where phase 2 plugs in:**
- `convex/lib/cleanup.ts`: `removeMembership` (leave or remove, per family) and `deleteUserData` (account deletion) have marked spots for walks, statuses, feed events, reactions, devices and mutes.
- `steps.ts` `applyLateSync` has a marked spot for the "family hit the goal" event when a late sync flips a day.
- Today's 50% and 100% events belong in `syncSteps`.

## Context
- Read `docs/PRD.md` first (F1–F8 are this phase; F9–F16 are phase 2 — leave room for them in the schema but don't build them).
- Approved npm dependencies (only these; ask in the handoff for anything else): `convex`, `jose`, dev: `typescript`, `vitest`, `convex-test`, `@edge-runtime/vm`. Add scripts `typecheck` (`tsc --noEmit -p convex`) and `test` (`vitest run`).
- **Auth (F1).** The iOS app does native Sign in with Apple and gets an Apple identity token (lives 10 min, can't be refreshed client-side). So:
  - HTTP action `POST /auth/apple` {identityToken, fullName?} verifies the token with `jose` against Apple's JWKS (`https://appleid.apple.com/auth/keys`), iss `https://appleid.apple.com`, aud = env `APPLE_BUNDLE_ID` (default `com.bixustudio.hamrosteps`). It upserts the user by Apple `sub`, then issues our own RS256 access JWT (1 h) and an opaque refresh token (stored hashed, 90 days, rotated on use) via `POST /auth/refresh`, plus `POST /auth/logout`.
  - Serve our JWKS at `/.well-known/jwks.json`. Register it in `convex/auth.config.ts` as a `customJwt` provider, so `ctx.auth.getUserIdentity()` works in queries and mutations. The signing key comes from env `JWT_PRIVATE_KEY` (PKCS8 PEM). Tests generate a throwaway key; no key is ever committed.
  - Sessions stay signed in across restarts (refresh). Display name from Apple's fullName on first sign-in, else the user types one (the only typing in the join flow).
- **Account deletion (F1).** `deleteMyAccount` action/mutation removes the user and everything they shared: memberships, steps, sessions, devices (phase 2 tables included later). Ownership passes to the earliest-joined remaining member, and an empty family is deleted. Also revoke the Apple token via Apple's `/auth/revoke` when env `APPLE_TEAM_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY` are set; skip with a log line when not. Keep it behind a small function the tests can stub.
- **Families (F2, F3).**
  - `createFamily(name, dailyGoal = 50000)`: the caller becomes organiser. Goal range 1,000–1,000,000. Name 1–40 chars.
  - Invite code: 6 chars from `ABCDEFGHJKMNPQRSTUVWXYZ23456789`, unique. `joinFamily(code)` is case/space/dash-insensitive and idempotent. Max 8 members ("family is full" error). `regenerateInviteCode` and `removeMember` are organiser only. `updateFamily(name, dailyGoal)` is organiser only. `leaveFamily`.
  - Leaving or being removed deletes that member's shared data from that family: their membership, and in phase 2 their events and reactions. Their steps rows are per user, so they simply stop counting there.
  - A user can be in several families (`myFamilies` for the Home switcher).
  - Fixed family order = join order, organiser first; store `position`, never rank by steps.
  - Errors: throw `ConvexError({code: "..."})` with stable codes the app switches on (`not_authenticated`, `invalid_code`, `family_full`, `not_member`, `not_organiser`, `invalid_goal`, `invalid_name`, `invalid_steps`, `invalid_day`).
- **Steps (F4, F5).**
  - `syncSteps(days: [{day: "YYYY-MM-DD", steps}])` writes per-user rows keyed by **Nepal day** (Asia/Kathmandu, UTC+5:45). The iOS app buckets HealthKit by Nepal-midnight boundaries and sends today plus up to the previous 6 days. Reject days in the future (Nepal) or older than 7 days, and steps outside 0–200,000.
  - Each write replaces the value and sets `lastSyncedAt` on the user. Put the Nepal-day helpers in one module (`convex/lib/nepalDay.ts`) with unit tests around the 18:15 UTC boundary.
- **Home (F6–F8).**
  - `familyToday(familyId)` (reactive query): `{family, day, goal, total, percent, members: [{userId, name, avatarColor, position, isOrganiser, steps | null, lastSyncedAt | null, status: null /* phase 2 */}]}` in fixed order. A member with no row for today gives `steps: null` ("not synced yet"), never 0.
  - `familyWeek(familyId)`: the 7 Nepal days Monday–Sunday of the current Nepal week, each `{day, total, goal, hit, isFuture}`.
  - Cron at Nepal midnight (`crons.ts`, 18:15 UTC daily) closes the day: snapshot each family's total/goal/hit into `familyDays`, so a later goal change doesn't rewrite history. `familyWeek` uses the snapshots for closed days and live totals for today.
- Every public function checks auth and membership. Use `internalMutation` for anything the cron or HTTP actions call. Indexes for every lookup; no `.filter` table scans.
- Profiles: `avatarColor` (hex picked from an 8-colour palette on creation), `name`, `timezone` (stored, informational). No emoji avatars.

### Libraries

- **Hugeicons** (icons): Use Hugeicons for every icon in the UI, keeping one style and stroke weight throughout and colouring with currentColor. No emoji and no hand-drawn SVG icons.
- **Thinking Orbs** (loading): Use Thinking Orbs for every AI "thinking" or loading state instead of a spinner. On web render <ThinkingOrb state="..." size={64|20} /> and pick the state that matches the activity (e.g. searching, composing). Set up: Web: `npm install thinking-orbs`; Mac: `Swift Package Manager: add https://github.com/Jakubantalik/Libraries.dev (branch main), product ThinkingOrbsKit`; iOS: `Swift Package Manager: add https://github.com/Jakubantalik/Libraries.dev (branch main), product ThinkingOrbsKit`. iOS: The page doesn't explicitly say the Swift package supports iOS or macOS, and it gives no CocoaPods option. Mac: The page doesn't explicitly say the Swift package supports macOS; SwiftUI support is implied only. Web: Requires React 18 or newer; the page lists only an npm install line.

### Releasing

- Pushing the default branch isn't a release: each project's Jarvis
  commits and pushes its own main (a plain fast-forward) and never leaves
  the push for the user, unless the project marks main as a release
  (`gates.default_branch_is_release: true`).
- Releasing is the user's: Ultron blocks agents from tagging, force-pushing,
  deploying to production or submitting to a store. Ask the user to do it.
- Every release gets a changelog entry in the user's voice: what changed for
  the person using the app, not which files moved.
- Version numbers are semantic. A release that changes stored data bumps
  the minor version and ships a migration with a rollback note.
- Preview or staging deployments are fine without the user; say where the
  preview is in the handoff.

# ios-push round 4: from Jarvis

The round-4 second opinion is Blocking again (handoffs/reviews/2026-11-14-1600-ios-push-second.md, findings 1 and 2):
1. A stale registration from account A, abandoned after the settle timeout, finishes after B registers and takes the token back.
2. finishSession clears its state before awaiting auth.signOut, so a slow logout can be overtaken by the next sign-in and deauthenticate it.

Stop patching timeouts. Change the design:
- ONE serial queue (an actor) owns every register, every unregister and the whole sign-out, including auth.signOut. Nothing is abandoned on a timeout. The next sign-in awaits that queue until it's empty.
- Bound each network call with its own request timeout instead, so the queue can't hang forever.
- A registration started for account A always finishes, or is cancelled, before any work for account B starts.
- Delete code the old timeout/generation approach no longer needs.

Tests, both with suspendable fakes:
- A's registration finishes after B registers: B must still own the token.
- A suspended signOut can't be overtaken by a new sign-in.

Then run `ultron check` until it's green, put the real result in Checks run, add a "## Redo (round 4)" section, and hand off again.
